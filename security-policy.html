Security & Privacy

How we protect your checkout and data

Last updated: September 2026

Overview

Fashion_Fussion operates an authenticated ecommerce checkout. Product totals, GST, promotions, delivery charges and payment-method charges are calculated on the server before an order is finalized.

Payment model: prepaid payments use Razorpay-hosted checkout and are verified server-side. Cash on Delivery is also available. COD carries a ₹49 non-refundable charge. Prepaid checkout shows a ₹49 payment discount, which offsets the ₹49 payment handling charge.

We do not ask you to enter card numbers, CVV values, UPI PINs or net-banking passwords into Fashion_Fussion pages. Prepaid payment credentials are handled by Razorpay's payment interface.

Payment security and recovery

  • Razorpay orders are created by the backend using server-side credentials.
  • The browser cannot set the authoritative product price, GST rate, discount or final payable amount.
  • Prepaid responses are cryptographically verified on the server and the captured payment is cross-checked against the stored order, user and amount.
  • Order finalization and promotion consumption are performed atomically and idempotently to reduce duplicate or partially-completed processing.
  • If a browser callback is interrupted, the checkout includes server-side reconciliation support. Customers should check My Orders before attempting a second payment.
  • COD orders do not pass through Razorpay. The ₹49 COD charge is recorded on the order and is non-refundable.

Account and database security

  • Checkout requires an authenticated Supabase account.
  • Row Level Security is used on customer-facing database tables to restrict records by the signed-in user and administrator role.
  • Administrator-only product cost data is not exposed through the public catalog.
  • Cart data may be stored in the browser, but final checkout values are recalculated by the backend.

Third-party services

Fashion_Fussion uses Supabase for authentication/database services, Razorpay for prepaid payment processing, GitHub Pages for the public storefront, and Vercel for backend API hosting.

Data retention

Account, address, order, payment-reference and support records may be retained as reasonably required to operate the store, provide support, prevent fraud and meet accounting or legal obligations.
